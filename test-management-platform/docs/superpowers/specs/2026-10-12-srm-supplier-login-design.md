# SRM 供应商登录自动化设计

## 目标

为中科创达采购协同平台开发一条可独立执行的供应商登录自动化测试。测试登录地址为 `https://shijiedev.thundersoft.com/srm/login`；成功条件是浏览器进入 `/srm/supplier/home`。

首期只交付独立的 Playwright 测试，不连接测试管理台的执行中心。脚本真实运行通过后，再单独规划运行批次、报告和证据回传的接入工作。

## 范围

测试覆盖以下正向流程：

1. 打开 SRM 登录页。
2. 选择供应商登录入口（若页面默认不是供应商入口）。
3. 输入供应商账号和密码。
4. 提交登录。
5. 等待页面跳转，并断言路径为 `/srm/supplier/home`。
6. 断言供应商首页已完成加载，避免只校验 URL 而未完成登录。

首期不覆盖验证码、短信/邮箱登录、飞书 SSO、忘记密码、注册或账户锁定。

## 文件与运行方式

新增：

- `playwright.config.ts`：Chromium、超时、失败重试及报告输出配置。
- `e2e/srm-supplier-login.spec.ts`：供应商密码登录场景。
- `scripts/run-srm-supplier-login.ps1`：交互式启动脚本，安全提示输入凭据后仅传给当前测试进程。
- `e2e/README.md`：安装、执行、故障排查说明。

根目录增加 `e2e:srm-supplier-login` 命令，供已在当前进程设置凭据的场景执行。

## 凭据与数据保护

测试脚本只读取 `SRM_SUPPLIER_USERNAME` 和 `SRM_SUPPLIER_PASSWORD` 环境变量。不得将凭据写入代码、Git、测试日志、HTML 报告、截图或录像。

交互脚本使用 PowerShell 凭据提示框，凭据仅保留在该命令进程的环境变量中，进程结束即失效。仓库会忽略 `.env`、Playwright 结果目录及临时日志。

## 证据与保留位置

Playwright 的 HTML 报告、失败截图、视频、trace 和测试结果写入：

`D:\路径卷不可删\test-management-platform\playwright-*`

不在 E 盘代码目录写入运行数据。成功运行保留简要 HTML 报告；失败运行保留截图、视频与 trace，后续按平台现有的一周保留策略清理。

## 页面定位策略

优先使用用户可见且稳定的定位方式：供应商文本、用户名输入框占位文本、密码输入框占位文本和登录按钮。测试不依赖 CSS class、构建 hash 或内部组件结构。

登录页面元素若发生改变，测试会自动保留失败证据；只调整定位器后再重跑，不能跳过最终首页断言。

## 验收标准

- 缺少凭据时，命令给出明确提示，不发起登录请求。
- 使用有效供应商测试账号时，Chromium 登录并进入 `/srm/supplier/home`。
- 登录失败或元素不可见时，命令非零退出，D 盘生成可查看的失败证据。
- 凭据不会出现在仓库、测试输出或报告中。
